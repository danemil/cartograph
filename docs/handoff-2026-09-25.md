## Where the conversation actually stopped

**Waiting on a human, not on code.** The user downloaded the repo onto a clean
Windows machine and was given install instructions. No results came back.

They downloaded the *source*, which does not contain the extension — the `.vsix`
is gitignored and ships as a Release asset. They were told to fetch
`carto-win32-x64-0.1.0.vsix` from the v0.1.0 release instead.

Two things flagged to them that may explain silence:

1. Their folder was named `#Cartograph`. `#` is a PowerShell comment character
   and the fragment separator in file URIs, which is how a VS Code extension
   resolves paths. They were told to rename it. If they did not, expect
   baffling unrelated-looking errors.
2. The binary is unsigned, so SmartScreen may block it. That needs a signing
   identity, not a code change.

**First question to ask them:** what happened on Windows — including "nothing
appeared to happen", which is the more likely failure shape than an error.

The four checks they were asked to run, in a scratch repo:
`carto --version` resolves in a NEW terminal (PATH injection, never tested);
status bar appears (never tested); `carto status --format json` reports nodes
above zero; Copilot Chat can answer "what does the review-changes skill say"
(host-side skill discovery, never tested).

## Conventions that are not obvious and have been enforced

- **Comments explain WHY, never what.** Understated, factual. `envelope.py`,
  `review_shape.py` and `repo_paths.py` set the register; match them.
- **Reuse, never a second copy.** This project has fixed that defect class
  three times (three copies of the skills pack; two of the path helpers; two
  precondition-exit paths). If something must be shared, MOVE it and rewire
  callers.
- **A conformance op that cannot fail is worthless.** The suite has passed
  while real defects were live, twice. Prove each new op fails without the fix.
  One was silently vacuous because it sat below an early `return`.
- **Verify subagent and document claims against the shipped artifact.** Vault
  documents have named commands and flags that do not exist, repeatedly.
  `contracts/capability-v1/check_skills.py` exists because the designed skills
  named five nonexistent flags.
- **Never rename the `.code-review-graph` literals** (`LEGACY_DATA_DIR`,
  `LEGACY_DB_FILE` in `incremental.py`). They identify pre-rename state. A
  blanket sed renamed them once and silently disabled legacy migration and half
  of `uninstall`.
- **Use an ABSOLUTE `PYTHONPATH`** when testing hooks. `spawn_detached` sets
  `cwd` to the target repo, so a relative `PYTHONPATH=engine` fails invisibly
  behind `DEVNULL` and looks exactly like "detaching does not work".
- **The hook protocol is not the query protocol.** In a hook, exit `2` means
  *blocking feedback to the model*. `hook.py` touches no envelope helper and
  always exits 0; an AST-walking test enforces it.

## Decided — do not relitigate

- Storage is SQLite + `sqlite-vec`. FalkorDB rejected (SSPLv1, needs a daemon);
  Chroma rejected (no embedded Node mode).
- The memory capability is **Python inside the engine**, not a TypeScript fork.
  `memory/` was deleted; claude-mem is a design reference with no code taken.
  See `PROVENANCE.md` and the root `NOTICE`, both corrected to say so.
- MCP registration is opt-in (`--with-mcp`), off by default.
- The `.vsix` is the primary delivery vehicle; installing it also serves Claude
  Code and Copilot CLI.
- The CI Linux job builds in `python:3.12-slim-bookworm` on purpose. PyInstaller
  bundles libpython but not libc. Do not "modernise" it — there is a comment
  saying so.

## Two corrections worth carrying forward

Both are cases where a confidently-stated fact was wrong, and are the reason the
"verify against the artifact" habit above exists.

- **`tree_sitter_language_pack` is ~5MB, not 351MB.** The 351MB figure came from
  the project's own design record and was repeated without measuring. 1.x is a
  small extension that fetches grammars at runtime; only 0.x bundled them. The
  import costs ~22ms. `PROVENANCE.md` defect 7 is now version-accurate, which
  matters because it is offered upstream as a PR.
- **A false "isolated commit" claim.** `PROVENANCE.md` said each upstream fix
  was kept as an isolated commit against pristine upstream. No such branch
  existed. The `pre-rename` tag and `upstream-fixes` branch now exist and are
  pushed; they are the only thing keeping those 9 PRs extractable.
